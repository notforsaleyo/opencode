# 전역 환경 동기화

## 위치와 범위

- 저장소 루트는 이 파일 기준 `../..`이다. 현재 프로젝트의 Git 저장소와 혼동하지 않는다. 실행 전 해당 폴더가 `opencode debug paths config`의 활성 전역 설정 폴더이자 의도한 Git 저장소인지 확인한다. 다른 컴퓨터에서 복원이 아직 안 됐다면 `README.md`의 최초 복원 절차를 먼저 따른다.
- 저장소의 `AGENTS.md`, `README.md` 및 현재 브랜치, 원격, staged/unstaged/untracked 상태를 읽는다. 활성 에이전트가 읽기 전용이면 변경·Git 동기화를 실행하지 않는다.
- 요청의 방향을 분명히 한다. 가져오기 = 원격 변경을 로컬에 통합하고 기기에 적용하기. 올리기 = 공유할 로컬 설정을 커밋하고 원격으로 전송하기. 단순 상태 조회는 fetch, 커밋, push를 수행하지 않는다. 방향을 알 수 없으면 묻는다.
- 설정 대상은 `AGENTS.md`, `README.md`, `.gitignore`, `cli.json`, `opencode.jsonc`의 MCP 이외 항목, `dcp.jsonc`, `skills/`, `custom-plugins/`, `shared/`, 그리고 사용자 요청에 포함된 설정용 `commands/`, `agents/`, `themes/`다. `backlog/`와 `handoff/`는 기본 올리기 대상이 아니다. 특히 `handoff/`는 원문 대화이므로 명시적 요청과 해당 스킬의 규칙 없이 커밋하지 않는다. 파일의 위치만으로 안전을 가정하지 않고 변경 내용을 확인한다.
- **모든 MCP 서버 설정은 동기화하지 않는다.** 로컬/원격 및 활성/비활성 모두 동일하다. `opencode.jsonc`의 `mcp` 항목과 다른 추적 파일에 들어간 MCP 서버 정의·인증·설치 안내를 공유 설정으로 추가하지 않는다. MCP용 독립 파일과 `mcp/` 폴더는 `.gitignore`로 제외한다. `.gitignore`는 이미 추적 중인 파일의 JSON 항목을 가려주지 못하므로, 커밋 전 반드시 내용을 확인한다. DCP 플러그인은 MCP 서버 설정이 아니므로 이 제외 규칙에 포함되지 않는다.
- 인증, 서비스 등록, 세션 DB, 로그, 캐시, `node_modules/`, 가상환경, 실행 파일 및 비밀 값은 저장소에 올리지 않는다. `.gitignore`를 우회해 `git add -f` 하지 않는다. 기존 staged 작업, 로컬 변경, 원격 변경을 버리지 않는다.

## 기기별 값의 원칙

- 공유 가능한 경로는 이식 가능한 표현을 우선한다. 두 Codex 래퍼 플러그인 경로는 각각 `cli.json`, `opencode.jsonc` 기준 `./custom-plugins/...`이다. 전역 설정 폴더 위치를 먼저 확인하고, 필요한 `node_modules`는 README 절차로 기기별 설치한다.
- 이 저장소의 기기별 항목을 실제로 점검한다: `shared/wezterm.lua`와 실제 `%USERPROFILE%\.wezterm.lua`의 글꼴, 크기, PowerShell, Sublime Text; 실제 mise 전역 설정과 PowerShell 프로필. `cli.json`, `opencode.jsonc`, 새 스킬/플러그인 설정에 추가된 절대 경로도 함께 찾는다. MCP 서버 경로는 동기화에서 제외한다. 사용자 이름만 치환해서 임의의 설치 경로를 만들어 내지 않는다.
- 환경 변수, 설치 경로, `Get-Command`, 설치 파일 및 실제 사용 중인 설정으로 존재를 확인한다. 자동 탐색으로 한 후보만 확실하면 이 기기에 반영한다. 후보가 여러 개거나 없으면 기존 유효한 로컬 값을 유지하고 질문하거나 적용 대기 상태로 보고한다. 비활성 도구를 멋대로 켜지 않는다. 기존 로컬 값이 원격과 다르다는 이유만으로 사용자 취향(글꼴, 크기, 설정)을 덮지 않는다.
- Git으로 추적하는 활성 `cli.json`/`opencode.jsonc`에는 별도의 로컬 오버레이가 자동 적용되지 않는다. 기기별 경로나 개인 MCP를 이 파일에 넣으면 로컬 수정으로 남고, 이후 다른 기기에서 가져오기와 충돌할 수 있다. 먼저 상대 경로나 지원되는 환경 변수 방식처럼 동작을 검증할 수 있는 이식형 표현을 검토한다. 불가능하면 로컬 수정을 보존하고 올리기에서는 해당 변경을 제외한다. 같은 파일의 공유 변경과 로컬 전용 변경이 섞이면 명시적 hunk 단위 검토로 공유 부분만 포함한다. 무충돌 자동 동기화를 보장하는 척하지 않는다.
- `shared/wezterm.lua`는 공유본이고 `%USERPROFILE%\.wezterm.lua`는 실제 적용본이다. 양쪽의 비기기별 설정 변경은 대조해 동기화하되, 기기별 값은 로컬 기존 값을 우선한다. 적용 전 실제 파일의 차이와 백업 여부를 검토한다. 설치되지 않은 WezTerm이나 편집기는 자동 설치하지 않는다. 다른 기기에서 변경된 설정을 그대로 복사하지 말고 필요한 부분을 병합한다.

## 가져오기

1. 저장소, 활성 설정 폴더, 원격/브랜치와 `git status --porcelain=v1 -uall`, `git diff`, `git diff --cached`를 확인한다. 로컬 설정과 실제 WezTerm·mise·프로필의 차이도 확인한다.
2. `git fetch origin` 후 업스트림과 로컬 커밋의 차이 및 변경 파일을 검토한다. 원격 `opencode.jsonc`나 다른 파일에 MCP 서버 정의가 있다면 이를 이 기기에 적용하지 않는다. 이미 존재하는 로컬 전용 MCP를 훼손하지 않고 별도로 보존할 수 없으면 병합을 중단한다. 다른 동기화 제외 항목이나 민감한 원격 변경도 사용자가 모르게 삭제하거나 덮지 않는다.
3. 미커밋·staged 변경을 손상시키지 않고 통합 가능한 경우에만 업스트림을 병합한다. 기본은 fast-forward, 양쪽에 커밋이 있으면 충돌 가능성을 검토하고 일반 병합한다. 자동 stash, 강제 checkout/reset, `git pull --rebase`로 로컬 변경을 숨기거나 재작성하지 않는다. 막히면 보존한 채 원인과 파일을 보고한다.
4. 기기별 값은 위 원칙에 따라 현재 기기에서 확인해 적용한다. 공유 WezTerm 변경은 실제 파일에 필요한 부분만 반영한다. mise 설정과 프로필도 기존 내용을 보존하며 공유할 부분만 병합한다. 새 의존성이 있으면 README를 따라 설치·검증하되, 권한/설치 조건이 없으면 미적용으로 보고한다.
5. 적용 여부, 원격 반영 결과, 남은 로컬 변경, 기기별 미해결 항목을 분리해서 짧게 알린다. fetch만 성공했거나 병합이 막혔다면 "가져오기 완료"라고 하지 않는다.

## 올리기

1. 실제 적용본과 공유본의 차이를 대조한다. 공유할 WezTerm·mise·프로필 변경은 관련 파일에 반영하되 기기별 경로·취향을 타 기기 기본값으로 덮지 않는다. 복원 방법이 달라지면 README도 갱신한다.
2. `git status`, staged/unstaged diff, untracked 파일, 업스트림을 확인한다. 바뀐 각 파일과 추가될 내용의 비밀 정보·기기별 경로·MCP 서버 정의를 검사한다. MCP는 사용자 지정 파일에 섞여 있어도 공유 커밋에서 제외한다. 의심스러운 값이 있으면 제외하거나 사용자에게 확인한다. 사용자가 별도 범위를 지정하면 그 범위만 처리한다.
3. 변경 파일 중 공유 가능한 설정만 정확한 경로로 stage한다(`git add -A -- <경로...>`). 저장소 전체를 무차별 추가하지 않는다. staged 변경이 미리 있었다면 커밋 대상에 끼워 넣지 않는다. 대상 파일 전체가 공유 가능할 때만 `git commit --only -- <경로...>`로 기존 stage를 보존한다. 같은 파일에 제외할 기기별 hunk가 섞여 있으면 `git commit --only`는 **파일 전체를 커밋하므로 사용하지 않는다**. 기존 index를 보존하는 격리된 임시 index 등으로 공유 hunk만 안전하게 커밋할 수 없다면 중단하고 알린다. 임시 index를 쓸 때도 원래 index와 작업 파일은 훼손하지 않는다.
4. 공유 설정만 커밋한 뒤 fetch해 업스트림을 안전하게 통합하고 일반 `git push`를 수행한다. 원격 선행 커밋이나 push 거절 시 재확인하고 해결 가능한 경우에만 병합·재시도한다. `--force`를 쓰지 않는다. 커밋할 변경이 없어도 로컬 선행 커밋의 push가 요청 범위에 맞는지 확인한다.
5. 커밋 해시, push 성공 여부, 제외한 로컬 기기별 변경을 구별해 보고한다. 커밋만 됐거나 push에 실패했으면 백업 완료라고 하지 않는다.

## 관계된 작업

- 대화 보관·복원·삭제는 `session-handoff`, 개인 백로그 작업은 `personal-backlog`를 따른다. 이 스킬의 설정 동기화 요청만으로 해당 데이터를 새로 작성하거나 공개 원격에 전송하지 않는다.
- 복원한 설정의 플러그인 로딩과 경로를 확인하고 가능한 경우 `opencode plugin list`, WezTerm 설정 로딩 등을 점검한다. MCP 설정을 설치·복원·검증하지 않는다. 현재 서비스 재시작이 필요하면 사용 중인 세션에 영향을 설명하고 안전한 시점에 한다.
