# 전역 환경 동기화

## 위치와 범위

- 저장소 루트는 이 파일 기준 `../..`이다. 현재 프로젝트의 Git 저장소와 혼동하지 않는다. OpenCode·mise 등이 이미 준비된 컴퓨터의 **설정 파일 동기화 전용**이다. 실행 전 해당 폴더가 `opencode debug paths config`의 활성 전역 설정 폴더이자 의도한 Git 저장소인지 확인한다. 아직 설정 저장소가 활성 폴더에 없다면 그 사실을 알리고 무단으로 설치·초기 환경 구축을 하지 않는다. WezTerm·Obsidian 설치 여부는 파일 동기화의 전제 조건이 아니다.
- 저장소의 `AGENTS.md`, `README.md` 및 현재 브랜치, 원격, staged/unstaged/untracked 상태를 읽는다. 활성 에이전트가 읽기 전용이면 변경·Git 동기화를 실행하지 않는다.
- 요청의 방향을 분명히 한다. 가져오기 = 원격 변경을 로컬에 통합하고 기기에 적용하기. 올리기 = 공유할 로컬 설정을 커밋하고 원격으로 전송하기. 단순 상태 조회는 fetch, 커밋, push를 수행하지 않는다. 방향을 알 수 없으면 묻는다.
- 설정 대상은 `AGENTS.md`, `README.md`, `.gitignore`, `cli.json`, `opencode.jsonc`의 MCP 이외 항목, `dcp.jsonc`, `skills/`, `custom-plugins/`, `shared/`, 그리고 사용자 요청에 포함된 설정용 `commands/`, `agents/`, `themes/`다. `backlog/`와 `handoff/`는 기본 올리기 대상이 아니다. 특히 `handoff/`는 원문 대화이므로 명시적 요청과 해당 스킬의 규칙 없이 커밋하지 않는다. 파일의 위치만으로 안전을 가정하지 않고 변경 내용을 확인한다.
- **모든 MCP 서버 설정은 동기화하지 않는다.** 로컬/원격 및 활성/비활성 모두 동일하다. `opencode.jsonc`의 `mcp` 항목과 다른 추적 파일에 들어간 MCP 서버 정의·인증·설치 안내를 공유 설정으로 추가하지 않는다. MCP용 독립 파일과 `mcp/` 폴더는 `.gitignore`로 제외한다. `.gitignore`는 이미 추적 중인 파일의 JSON 항목을 가려주지 못하므로, 커밋 전 반드시 내용을 확인한다. DCP 플러그인은 MCP 서버 설정이 아니므로 이 제외 규칙에 포함되지 않는다.
- 인증, 서비스 등록, 세션 DB, 로그, 캐시, `node_modules/`, 가상환경, 실행 파일 및 비밀 값은 저장소에 올리지 않는다. `.gitignore`를 우회해 `git add -f` 하지 않는다. 기존 staged 작업, 로컬 변경, 원격 변경을 버리지 않는다.

## 기기별 예외와 공유 설정

- 기기마다 조정할 설정은 실제 `.wezterm.lua` 옆 `.wezterm.local.lua`의 `baseFont`·`fontSize`·`powershell`·`sublimeEditor` 오버라이드이다. 사용자 이름은 독립적인 설정 예외가 아니다. 경로에 사용자 프로필 이름이 포함될 수 있을 뿐이며, 그럴 때도 실제 설치 위치를 확인한다. 모든 MCP 서버 설정은 동기화에서 제외한다. `shared/wezterm.lua`의 글꼴·크기·프로그램 경로는 공유 기본값이며 색상, 단축키, 창 설정 등도 공유한다. 별도 지시 없이 로컬 선호도라 추정해 공유본 적용을 건너뛰지 않는다.
- 공유 가능한 경로는 이식 가능한 표현을 우선한다. 두 Codex 래퍼 플러그인 경로는 각각 `cli.json`, `opencode.jsonc` 기준 `./custom-plugins/...`이다. 전역 설정 폴더 위치를 먼저 확인한다. `node_modules`나 다른 의존성을 설치하지 않는다.
- 기기별 외부 응용프로그램 경로를 실제로 점검한다: `shared/wezterm.lua`의 기본값과 실제 `.wezterm.lua` 옆 `.wezterm.local.lua`의 PowerShell·Sublime Text 경로, `cli.json`·`opencode.jsonc`·새 스킬/플러그인 설정의 외부 응용프로그램 절대 경로. 사용자 프로필이 포함된 절대 경로도 같은 방식으로 확인한다. MCP 서버 경로는 동기화에서 제외한다. 사용자 이름만 치환해서 임의의 설치 경로를 만들어 내지 않는다.
- 환경 변수와 기존 설정 파일에서 외부 응용프로그램 경로를 확인하고, 파일 위치가 필요할 때만 해당 경로의 존재를 확인한다. 한 후보만 확실하면 WezTerm 경로는 이 기기의 `.wezterm.local.lua`에 반영하고, 다른 설정의 경로는 해당 기기에 맞춘다. 후보가 여러 개거나 없으면 기존 로컬 경로를 보존하고 질문하거나 해당 경로의 적용 대기 상태를 보고한다. 응용프로그램을 실행해 동작을 시험하거나 새로 설치하지 않는다.
- Git으로 추적하는 활성 `cli.json`/`opencode.jsonc`에는 별도의 로컬 오버레이가 자동 적용되지 않는다. 기기별 경로나 개인 MCP를 이 파일에 넣으면 로컬 수정으로 남고, 이후 다른 기기에서 가져오기와 충돌할 수 있다. 먼저 상대 경로나 지원되는 환경 변수 방식처럼 동작을 검증할 수 있는 이식형 표현을 검토한다. 불가능하면 로컬 수정을 보존하고 올리기에서는 해당 변경을 제외한다. 같은 파일의 공유 변경과 로컬 전용 변경이 섞이면 명시적 hunk 단위 검토로 공유 부분만 포함한다. 무충돌 자동 동기화를 보장하는 척하지 않는다.
- `shared/wezterm.lua`는 공유본이고 `%USERPROFILE%\.wezterm.lua`는 실제 적용본이다. 실제 파일은 같은 폴더의 선택적 `.wezterm.local.lua`를 읽어 `baseFont`·`fontSize`·`powershell`·`sublimeEditor`를 덮어쓴다. 파일이나 각 항목이 없으면 공유 기본값을 사용한다. 이 기기별 파일은 저장소 밖에 두고 Git에 올리지 않으며, 가져오기·올리기 모두에서 기존 내용과 존재 여부를 보존한다. 처음 분리할 때 실제 파일에만 있던 글꼴·크기·외부 프로그램 경로는 로컬 파일로 옮겨 보존하되, 이미 로컬 파일이 있다면 덮어쓰지 않고 차이를 확인한다. **가져오기**에서는 원격 공유본의 기본값, 색상·단축키 등 공유 설정을 실제 파일에 적용한다. 로컬 파일이 있으면 확인된 기기별 PowerShell·Sublime Text 경로를 해당 항목에 반영하되 다른 값은 보존한다. 로컬 파일이 없다면 공유 기본값만으로 적용하고 새로 만들지 않으며, 기본 경로가 유효하지 않으면 적용 대기 상태로 보고한다. **올리기**에서는 실제 파일의 공유 설정만 공유본에 반영한 후 커밋하며 로컬 파일의 오버라이드는 포함하지 않는다. 두 파일이 다를 때 방향을 무조건 공유본 → 실제 파일로 고정하지 않는다. WezTerm·편집기 설치나 설정 로딩 검사는 하지 않는다.
- `shared/mise-config.toml`은 실제 `%USERPROFILE%\.config\mise\config.toml`과, `shared/Microsoft.PowerShell_profile.ps1`은 실제 PowerShell `$PROFILE`의 mise 활성화 부분과 대응한다. 파일의 다른 사용자 설정은 보존하며 해당 공유 내용만 방향에 맞게 적용한다. 도구 설치·업그레이드·버전 확인은 하지 않는다.

## 가져오기

1. 저장소, 활성 설정 폴더, 원격/브랜치와 `git status --porcelain=v1 -uall`, `git diff`, `git diff --cached`를 확인한다. 로컬 설정과 실제 WezTerm·mise·프로필의 차이 및 실제 `.wezterm.lua` 옆 `.wezterm.local.lua`의 존재 여부도 확인한다.
2. `git fetch origin` 후 업스트림과 로컬 커밋의 차이 및 변경 파일을 검토한다. 원격 `opencode.jsonc`나 다른 파일에 MCP 서버 정의가 있다면 이를 이 기기에 적용하지 않는다. 이미 존재하는 로컬 전용 MCP를 훼손하지 않고 별도로 보존할 수 없으면 병합을 중단한다. 다른 동기화 제외 항목이나 민감한 원격 변경도 사용자가 모르게 삭제하거나 덮지 않는다.
3. 미커밋·staged 변경을 손상시키지 않고 통합 가능한 경우에만 업스트림을 병합한다. 기본은 fast-forward, 양쪽에 커밋이 있으면 충돌 가능성을 검토하고 일반 병합한다. 자동 stash, 강제 checkout/reset, `git pull --rebase`로 로컬 변경을 숨기거나 재작성하지 않는다. 막히면 보존한 채 원인과 파일을 보고한다.
4. 외부 응용프로그램 경로와 동기화 제외 MCP를 위 원칙에 따라 처리한다. 공유 WezTerm 파일을 실제 위치에 반영하고 `.wezterm.local.lua`가 있으면 기존 오버라이드를 보존한다. 로컬 파일이 존재하며 기기별 외부 프로그램 경로가 공유 기본값과 다르거나 기존 로컬 경로가 더 이상 유효하지 않다면 확인된 경로만 해당 파일에 반영하되 다른 값은 보존한다. 로컬 파일이 없다면 공유 기본값만으로 적용하므로 새로 만들지 않으며, 기본 경로가 유효하지 않으면 보고한다. mise 설정과 프로필도 대응 위치에 공유 내용만 반영한다. 파일의 존재와 내용만 확인한다. 설치, 업데이트, 프로그램 실행, 플러그인 로딩, 단축키·서비스 상태 확인은 수행하지 않는다.
5. 적용 여부, 원격 반영 결과, 남은 로컬 변경, 기기별 미해결 항목을 분리해서 짧게 알린다. fetch만 성공했거나 병합이 막혔다면 "가져오기 완료"라고 하지 않는다.

## 올리기

1. 실제 적용본과 공유본의 차이를 대조한다. 공유할 WezTerm·mise·프로필 변경은 관련 파일에 반영하되 외부 응용프로그램의 설치 경로를 다른 기기의 값으로 덮지 않는다. 사용자 이름이 포함된 경로도 설치 위치를 확인한다. `shared/wezterm.lua`의 기본값은 공유하되 `.wezterm.local.lua`의 기기별 `baseFont`·`fontSize`·`powershell`·`sublimeEditor`는 포함하지 않는다. 복원 방법이 달라지면 README도 갱신한다.
2. `git status`, staged/unstaged diff, untracked 파일, 업스트림을 확인한다. 바뀐 각 파일과 추가될 내용의 비밀 정보·기기별 경로·MCP 서버 정의를 검사한다. MCP는 사용자 지정 파일에 섞여 있어도 공유 커밋에서 제외한다. 의심스러운 값이 있으면 제외하거나 사용자에게 확인한다. 사용자가 별도 범위를 지정하면 그 범위만 처리한다.
3. 변경 파일 중 공유 가능한 설정만 정확한 경로로 stage한다(`git add -A -- <경로...>`). 저장소 전체를 무차별 추가하지 않는다. staged 변경이 미리 있었다면 커밋 대상에 끼워 넣지 않는다. 대상 파일 전체가 공유 가능할 때만 `git commit --only -- <경로...>`로 기존 stage를 보존한다. 같은 파일에 제외할 기기별 hunk가 섞여 있으면 `git commit --only`는 **파일 전체를 커밋하므로 사용하지 않는다**. 기존 index를 보존하는 격리된 임시 index 등으로 공유 hunk만 안전하게 커밋할 수 없다면 중단하고 알린다. 임시 index를 쓸 때도 원래 index와 작업 파일은 훼손하지 않는다.
4. 공유 설정만 커밋한 뒤 fetch해 업스트림을 안전하게 통합하고 일반 `git push`를 수행한다. 원격 선행 커밋이나 push 거절 시 재확인하고 해결 가능한 경우에만 병합·재시도한다. `--force`를 쓰지 않는다. 커밋할 변경이 없어도 로컬 선행 커밋의 push가 요청 범위에 맞는지 확인한다.
5. 커밋 해시, push 성공 여부, 제외한 로컬 기기별 변경을 구별해 보고한다. 커밋만 됐거나 push에 실패했으면 백업 완료라고 하지 않는다.

## 관계된 작업

- 대화 보관·복원·삭제는 `session-handoff`, 개인 백로그 작업은 `personal-backlog`를 따른다. 이 스킬의 설정 동기화 요청만으로 해당 데이터를 새로 작성하거나 공개 원격에 전송하지 않는다.
- 설정 파일이 요청한 위치에 놓였는지와 Git 결과만 확인한다. OpenCode·mise·WezTerm·Obsidian·플러그인을 설치하거나 실행해 검증하지 않는다. 서비스도 재시작하지 않는다. 플러그인·단축키 등 실제 동작은 사용자가 직접 확인한다. MCP 설정은 설치·복원·검증하지 않는다.
