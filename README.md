# 개인 OpenCode 환경과 백로그

OpenCode 전역 설정, 직접 만든 스킬·플러그인, 프로젝트 공통 백로그를 관리합니다.

## 구성

- `AGENTS.md`: 공통 응답 지침과 백로그 호출 조건
- `opencode.jsonc`: 서버·모델·플러그인 설정
- `cli.json`: 터미널 단축키와 화면 설정
- `dcp.jsonc`: DCP 설정
- `custom-plugins/`: 직접 수정한 플러그인 소스
- `skills/personal-backlog/`: 백로그 운영 절차와 양식
- `backlog/*.md`: 기억을 요청한 주제별 요약

백로그에는 원본 대화, 세션 ID, 대화 링크를 남기지 않습니다. 대화 배경과 핵심 내용, 현재 결론, 다음 행동만으로 이어갈 수 있게 작성합니다. 태그는 사용하지 않습니다.

## 사용

- “이 내용 나중에 할 일로 남겨 주세요.”
- “전에 OpenSpec 확장 얘기했던 것 찾아 주세요.”
- “우리 미뤄둔 일 목록 보여 주세요.”
- “그 항목 완료로 표시해 주세요.”
- “그 항목은 이제 잊어 주세요.”

미완료는 `open`, 완료는 `done`입니다. 완료 파일도 보존하고 회상 검색에 포함합니다. 잊기 요청은 파일을 삭제하지만 기존 Git 이력까지 제거하지는 않습니다.

## Git 관리와 동기화

이 폴더 자체가 로컬 Git 저장소입니다. 원격 저장소는 별도로 지정합니다. 개인 백로그를 포함하므로 비공개 저장소 사용을 권장합니다.

`.gitignore`는 루트에서 추적할 파일·디렉터리를 명시적으로 허용합니다. 새로운 설정 파일을 관리하려면 허용 목록에도 추가합니다. 서비스 정보, 로그인 정보, 의존성, 캐시, 로그, 대화·세션 데이터는 추적 대상이 아닙니다. 기본 OpenCode 세션 데이터 저장소도 이 저장소 밖에 있습니다.

파일을 등록·수정했다고 자동으로 commit/push하지 않습니다. “환경 동기화해 주세요”라고 요청하면 원격 연결과 로컬 변경을 확인하고 동기화합니다. 최초 원격 연결에는 저장소 URL이 필요합니다.

## 다른 기기에서 복원

1. OpenCode V2와 필요한 런타임을 설치합니다.
2. 기존 전역 설정이 있으면 먼저 보존하고 비교합니다. 빈 설정 위치에 이 저장소를 clone하거나 필요한 파일을 병합합니다.
3. 아래 플러그인 의존성과 경로를 맞춥니다.
4. 해당 기기에서 제공자 로그인을 진행합니다.
5. 새 세션에서 백로그 스킬이 보이는지, 단축키와 플러그인이 동작하는지 확인합니다.

`cli.json`은 터미널 설정이며 데스크톱 앱의 모든 설정을 포함하지는 않습니다.

### 현재 기기 의존성

기존 Codex 사용량 커스터마이징에는 다음 절대 경로가 있습니다.

- `opencode.jsonc`: `/home/notforsaleyo/.local/lib/node_modules/opencode-codex-usage/opencode2-plugin`
- `cli.json`: `/home/notforsaleyo/.config/opencode/custom-plugins/codex-usage-tui`
- `custom-plugins/codex-usage-tui/index.js`: 위 설치 패키지의 `dist/` 모듈을 직접 import

다른 기기에서는 `opencode-codex-usage`를 설치하고 이 경로들을 실제 위치에 맞춰야 합니다. 사용 중인 커스터마이징이 있으므로 패키지 버전과 API 호환성을 확인합니다. 현재 설정을 Git으로 보존하는 것만으로 의존성 설치나 경로 변환까지 자동 수행되지는 않습니다.
