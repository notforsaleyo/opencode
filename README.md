# 개인 OpenCode 환경과 백로그

컴퓨터와 프로젝트가 바뀌어도 익숙한 OpenCode 작업 환경과 기억해 둔 내용을 이어가기 위한 개인 저장소입니다.

단축키·화면 설정, 공통 지침, 스킬과 백로그를 보관합니다. 원본 대화와 세션 데이터는 포함하지 않습니다. 외부 확장은 각 컴퓨터에 별도로 설치하며, 기기 전용으로 사용하는 Codex 사용량 플러그인은 공유 대상에서 제외합니다.

## 새 컴퓨터에서 시작하기

WSL과 OpenCode TUI를 설치하고, 모델에 로그인해 대화할 수 있게 한 뒤 **파일 수정과 명령 실행이 가능한 에이전트**에게 아래 내용을 보내 주세요.

> https://github.com/notforsaleyo/opencode.git 는 제 OpenCode 환경 저장소입니다. 저장소를 받아 README의 에이전트용 환경 복원 지침을 읽고 이 컴퓨터에 적용해 주세요. 이후 백로그와 설정도 이 저장소로 계속 동기화할 수 있게 구성해 주세요.

설치·설정·검증은 에이전트가 진행합니다. 저장소 접근에 GitHub 인증이 필요하면 안내에 따라 인증해 주세요. OpenCode의 모델 로그인과 GitHub 인증은 별개입니다.

복원 후에는 **“OpenCode 환경 동기화해 주세요”**라고 요청하시면 됩니다. 공유 설정과 백로그를 Git으로 주고받고 실제 설정에 적용하는 작업까지 에이전트가 수행합니다.

## 에이전트용 환경 복원·동기화 지침

### 1. 현재 환경 확인

- 원격 저장소는 `https://github.com/notforsaleyo/opencode.git`이다. Git과 원격 접근을 확인하고, 필요하면 설치·인증을 안내한다. 인증 정보는 파일이나 원격 URL에 기록하지 않는다.
- 먼저 이 저장소의 `AGENTS.md`와 Git 상태·원격 연결을 확인한다. 기존 수정사항을 보존한다.
- 대상 기기의 OS, OpenCode 버전, 실제 전역 설정 위치, 런타임과 설치된 확장을 조사한다. 이 저장소는 OpenCode V2 기준이며, 설정 방법은 해당 버전 공식 문서에서 확인한다.
- WSL에서는 OpenCode 서비스가 실행되는 Linux 사용자의 설정 위치를 대상으로 한다. 보통 `~/.config/opencode/`이며, 환경변수나 실행 설정으로 위치를 바꾸었는지 확인한다.

### 2. 전역 설정 폴더를 저장소 작업 폴더로 연결

최종적으로 **활성 전역 설정 폴더 자체가 이 저장소의 Git 작업 폴더**여야 한다. 별도 clone에서 파일만 복사한 채 끝내지 않는다. 그래야 이후 `backlog/`와 `skills/` 변경이 같은 저장소에 잡힌다.

- 설정 폴더가 없거나 비어 있으면 그 위치에 clone한다.
- 설정 폴더에 파일이 있지만 Git 저장소가 아니면, 먼저 기존 파일을 저장소 밖에 백업한다. 별도 임시 위치에 clone하여 추적 파일을 비교·병합한 뒤, clone의 `.git` 메타데이터를 설정 폴더로 옮겨 그 폴더를 작업 폴더로 만든다. 로컬 `cli.json`, `opencode.json(c)`, 인증·서비스 정보와 기기 전용 플러그인은 유지한다. 임시 clone에서 계속 작업하지 않는다.
- 이미 이 저장소의 작업 폴더이면 기존 checkout을 사용한다. 다른 저장소의 `.git`이 있거나 상위 저장소에 속하면 덮어쓰거나 중첩 저장소를 임의로 만들지 말고 상황을 설명해 배치 방식을 확인한다.
- 원격 `origin`이 지정한 저장소인지 확인한다. 로컬 변경과 원격 변경을 비교하고 병합한다. `reset --hard`, 강제 checkout/push로 기존 작업을 버리지 않는다.
- `git rev-parse --show-toplevel` 결과가 활성 전역 설정 폴더인지 확인한다. `AGENTS.md`, `skills/`, `backlog/`가 실제 사용하는 위치이자 Git 추적 대상인지 확인한다.

### 3. 설정 적용 및 확장 설치

| 대상 | 에이전트가 수행할 작업 |
| --- | --- |
| `AGENTS.md`, `skills/` | 전역 지침과 스킬을 배치하고 발견 여부를 확인한다. |
| `shared/opencode.jsonc` | 전역 설정 폴더의 `opencode.jsonc`에 공유 설정을 적용한다. |
| `shared/cli.json` | 전역 설정 폴더의 `cli.json`에 터미널 단축키·화면 설정을 적용한다. 데스크톱 앱 전체 설정으로 간주하지 않는다. |
| `dcp.jsonc` | DCP 설정을 적용한다. |
| `backlog/` | 프로젝트 공통 기록을 보존·병합한다. 운영 절차는 `skills/personal-backlog/SKILL.md`를 따른다. |

현재 외부 확장 의존성은 다음과 같다. 실제 적용 시 설정 파일도 다시 확인한다.

- **`@tarquinen/opencode-dcp@3.2.0`**: `shared/opencode.jsonc`에 지정된 패키지다. OpenCode의 패키지 설치·로딩이 완료되었는지 확인한다.

`shared/`는 공유용 설정 보관 위치이며 OpenCode가 직접 읽는 설정 위치가 아니다. 새 환경에서는 위 표의 적용 위치에 복사하고, 기존 환경에서는 차이를 확인해 공유 설정을 병합한다.

Codex 사용량 플러그인(`opencode-codex-usage`, `custom-plugins/codex-usage-tui`)은 설치·복원·검증 대상에서 제외한다. 대상 기기에 이미 있으면 로컬 설정과 코드를 보존한다. 외부 패키지 설치물 자체를 Git에 복사하지 않는다.

### 4. 검증 및 완료 보고

- 설정 파싱·로딩, 공유 대상 외부 확장의 로딩, 전역 스킬 발견 여부를 확인한다.
- 단축키 설정이 적용되었는지 확인하고, 직접 확인할 수 없는 UI 동작은 미검증 사항으로 구분한다.
- 백로그가 현재 프로젝트가 아닌 전역 위치를 참조하는지 확인한다.
- `personal-backlog` 스킬을 로드하고 기존 백로그 항목을 읽어 조회가 가능한지 확인한다. 검증용 가짜 항목이나 완료 기록은 남기지 않는다.
- Git 원격과 작업 폴더 위치를 확인하고 `git ls-files`에 백로그·스킬·공유 설정이 포함되는지 확인한다. 실제 설정 파일과 Codex 사용량 플러그인이 제외되는지도 확인한다.
- 설정이 현재 세션에 반영되지 않았다면 필요한 새 세션 진입이나 재시작을 안내한다. 실행 중인 사용자 세션을 예고 없이 종료하지 않는다.
- 인증이 필요한 경우 해당 기기에서 로그인하도록 사용자에게 안내한다. 완료한 작업과 남은 사용자 조치를 짧게 보고한다.

완료 기준은 **전역 설정 적용, 공유 대상 확장 로딩, 백로그 조회, 같은 저장소에서 후속 변경을 추적할 수 있음**이다. 확인하지 못한 조건은 완료했다고 보고하지 않는다.

### Git 동기화 규칙

- 사용자 요청에 따라 동기화한다. 먼저 원격 연결과 미커밋 변경을 확인하고, 최초 연결에 필요한 원격 URL이 없으면 사용자에게 요청한다.
- 실제 사용하는 루트 `opencode.json(c)`와 `cli.json`은 기기 전용이며 Git에서 제외한다. 설정 변경을 내보낼 때는 로컬 파일과 `shared/`를 비교해 단축키 등 공유할 변경을 반영하되 Codex 사용량 플러그인 참조는 제외한다. 다른 플러그인 참조까지 일괄 삭제하지 않는다.
- 가져올 때도 `shared/` 변경을 실제 설정 파일에 적용해야 한다. Git pull만으로 적용되었다고 보고하지 않는다. `plugins` 배열을 포함한 기기 전용 설정을 보존하며 병합한다.
- 동기화 순서는 로컬 실제 설정의 공유 변경을 `shared/`에 반영 → 변경 검토·커밋 → 원격 fetch 및 병합 → 공유본을 실제 설정에 적용·검증 → push이다. 원격에서 바뀐 값을 오래된 로컬 설정으로 덮어쓰지 않도록 내보내기는 원격 병합 전에 수행한다. 사용자가 가져오기/내보내기만 요청하면 해당 범위에 맞춘다.
- 커밋 작성자 정보가 없으면 사용자에게 확인한다. 동기화 요청 범위 밖의 변경을 무조건 함께 커밋하지 않는다.
- 충돌은 양쪽 내용을 확인해 병합한다. 미커밋 변경을 버리거나 강제로 덮어쓰지 않는다.
- `.gitignore`는 추적 대상을 명시적으로 허용한다. 새 설정 파일이 필요하면 허용 목록을 함께 검토한다.
- 로그인 정보, 서비스 정보, 의존성 설치물, 캐시, 원본 대화·세션 데이터는 추가하지 않는다.
